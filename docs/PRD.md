## 1. 产品概述

### 1.1 产品定位

**EasyEpi** 是一款面向流行病学调查与临床研究领域的**本地化问卷设计与数据采集桌面应用**。产品核心理念：

- **向下兼容 EpiData**：无缝读入 `.qes` 和 `.rec` 文件，降低老用户迁移成本。
- **傻瓜式问卷设计**：通过可视化点击操作完成问卷构建，无需编程或编写脚本。支持在问卷完成后定义衍生变量（如 BMI、年龄分组），通过公式自动计算。
- **AI 辅助问卷设计**：在已创建并解锁的项目内，通过 DeepSeek 模型进行多轮对话，从零生成或持续精细化问卷；本地 Harness 负责格式、约束与安全校验。
- **一问一屏录入**：降低录入员的认知负荷，减少漏填与错填。
- **数据安全第一**：本地文件加密存储，管理员密码保护，保障敏感调查数据安全。
- **基线表一键生成**：内建流行病学常用统计表格生成功能，填补 EpiData 生态空白。

### 1.2 产品边界

| 维度 | 范围 |
|------|------|
| **平台** | Windows |
| **运行模式** | 核心工作流本地离线运行；AI 问卷助手为用户主动启用的可选联网功能 |
| **目标用户** | 流行病学研究者、临床研究协调员、公共卫生数据采集员 |
| **不做什么** | 在线问卷发放、复杂的统计分析（如回归模型）、多人实时协作 |

## 2. 目标用户与使用场景

### 2.1 用户画像

| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| **项目负责人 / PI** | 设计问卷、定义变量、设置逻辑规则 | 灵活的问卷设计、EpiData 迁移兼容、数据安全可控 |
| **数据录入员** | 按问卷逐题录入数据 | 操作简单、一问一屏、不易出错、可断点续录 |
| **数据管理员** | 查看/导出数据、生成基线表 | 数据导出为通用格式（CSV）、快速生成基线特征表 |
| **统计分析人员** | 获取清洗后数据进行后续分析 | 数据完整、变量标签清晰、格式与 R/SPSS/SAS 兼容 |

### 2.2 典型使用流程

```
研究准备阶段:
  [手工设计新问卷] 或 [AI 从零生成/精细化问卷] 或 [导入 EpiData .qes]
    → [设置跳题逻辑] → [设置 Key 标识符]
    → [定义衍生变量（可选）] → [保存项目]

数据采集阶段:
  [打开项目文件夹] → [录入问卷 #1] → [录入问卷 #2] → ... → [结束工作] → [查看录入份数]

数据管理阶段:
  [输入管理员密码] → [查看数据表格] → [生成基线表] → [导出 CSV]
```

## 3. 核心功能需求

### 3.1 问卷设计引擎

#### 3.1.1 支持的题型

| 题型 | 说明 | 典型应用 | 优先级 |
|------|------|----------|--------|
| **单选题** | 从预定义选项中选择一项 | 性别、是否患病 | P0 |
| **多选题** | 从预定义选项中选择多项 | 既往病史、症状列表 | P0 |
| **固定长度填空题** | 限制字符数的文本输入 | 身份证号（18位）、手机号（11位） | P0 |
| **不固定长度填空题** | 不限长度的文本输入 | 姓名、备注 | P0 |
| **条件筛选题** | 答案决定后续题目是否显示 | "是否吸烟"→选"否"则跳过吸烟相关题目 | P0 |

**核实结论**: ✅ 题型覆盖满足流行病学问卷基本需求。建议扩展见 [§4.1](#41-扩展题型)。

#### 3.1.2 题目属性

每道题目设计时需填写以下核心字段：

| 字段 | 说明 | 是否必填 |
|------|------|----------|
| **问题内容** | 显示给录入员的题目文本 | ✅ 必填 |
| **答案变量名** | 存储变量名（英文标识符，如 `sex`, `age`, `id_card`） | ✅ 必填 |
| **答案类型限制** | 定义允许的输入类型 | ✅ 必填 |
| **选项列表** | 单选/多选题的候选项 | 选择/多选时必填 |
| **默认值** | 预填值（可被修改） | 可选 |
| **是否为 Key 标识符** | 标记为个人标识变量 | 可选 |

#### 3.1.3 答案类型限制（答案约束）

| 约束类型 | 说明 | 校验方式 |
|----------|------|----------|
| **不限** | 任意字符均可输入 | 无校验 |
| **仅数字（整数）** | 只能输入 `0-9` | 正则 `^\d+$` |
| **仅数字（含小数）** | 允许小数点 | 正则 `^\d+\.?\d*$` |
| **仅文字（中文）** | 只允许中文字符 | Unicode 范围 `[一-鿿]` |
| **仅英文（字母）** | 只允许 `a-zA-Z` | 正则 `^[a-zA-Z]+$` |
| **英文＋数字** | 字母与数字组合 | 正则 `^[a-zA-Z0-9]+$` |
| **固定长度** | 必须恰好 N 个字符 | 长度校验 |  
| **逻辑（数值范围）** | `min ≤ value ≤ max`，可定义整数步长 | 范围校验 |
| **日期** | 标准日期格式 `YYYY-MM-DD` | 日期解析校验 |
| **正则表达式（高级）** | 用户自定义正则 | 正则引擎校验 |

**核实结论**: ✅ 覆盖常见约束场景。建议增加「日期类型」和「正则表达式自定义」作为高级选项。

#### 3.1.4 问题条件与跳题逻辑

**核心规则机制**:

```
IF [题目A] [操作符] [值] THEN [动作] [目标题目列表]
```

| 组件 | 可选值 |
|------|--------|
| **操作符** | `等于`、`不等于`、`大于`、`小于`、`包含`、`不包含`、`为空`、`不为空` |
| **逻辑连接** | `AND`（且）、`OR`（或），支持组合条件 |
| **动作** | `跳过（隐藏）`、`必填`、`显示` |

**用户操作流程**:

1. 在设计面板中选中某道「条件触发题」
2. 点击「添加条件规则」
3. 在弹出的规则编辑器中：
   - 选择触发条件（如：`第三题 等于 "否"`）
   - 勾选「满足条件时跳过以下题目」
   - 在题目列表中勾选需要跳过的题目
4. 一条规则可关联多道题目（批量跳转）
5. 支持多条规则组合（AND/OR 逻辑）

**可视化呈现**: 问卷设计面板中，有条件的题目旁边显示条件图标，点击可查看完整的跳题逻辑链。

**核实结论**: ✅ 设计合理。补充建议：
- 增加「条件预览」功能，以流程图方式显示跳题逻辑
- 增加「逻辑冲突检测」——当两条规则冲突时给出警告（如题目A在规则1中被跳过，但在规则2中被设为必填）

### 3.2 EpiData 项目导入

#### 3.2.1 .qes 文件解析

`.qes` 文件是 EpiData 的问卷定义文件，结构为纯文本格式（类似标记语言）。解析后自动生成完整的问卷结构。

**解析映射关系**:

| EpiData .qes 元素 | EasyEpi 映射 |
|-------------------|-------------|
| 变量名 (field name) | 答案变量名 |
| 变量标签 (field label / question text) | 问题内容 |
| 字段类型 (`#` 数字, `_` 文本, `<A>` 大写字母 等) | 答案类型限制 |
| 字段长度 (如 `##` = 2位整数) | 固定长度约束 |
| `COMMENT LEGAL` / `RANGE` / `MUSTENTER` 等块 | 校验规则 / 必填设置 |
| `JUMPS` 块 | 跳题逻辑（条件规则） |
| `LABEL` 块 | 选项值标签（单选/多选映射） |

#### 3.2.2 .rec 文件解析

`.rec` 文件是 EpiData 的固定宽度二进制数据文件。解析后生成数据记录。

**解析要点**:
- 文件头包含字段数量、字段定义（名称、类型、长度）
- 每条记录为固定宽度，按字段长度顺序排列
- 支持读取记录状态（正常记录 vs 已删除记录标记）
- 每个字段对应的值标签（label block）需要从 `.qes` 中获取

#### 3.2.3 导入流程

```
用户操作: [导入 EpiData 项目] → 选择 .qes 文件
  → 系统自动查找同目录同名 .rec 文件
  → 解析 .qes 生成问卷结构
  → 若存在 .rec，解析并导入数据
  → 显示导入摘要: 题目数 / 变量数 / 记录数 / 跳题规则数
  → 保存为 EasyEpi 项目格式 (.easyepi)
```

**核实结论**: ✅ 这是产品的核心差异化功能。EpiData 用户群体大（WHO 推荐工具），兼容导入可形成低门槛迁移优势。

**注意点**:
- `.qes` 不同版本 (EpiData 3.x vs EpiData Manager/Entry Client) 格式有差异，需分别适配
- `.rec` 文件编码取决于 EpiData 语言版本（中文版常用 GBK），需处理字符编码
- 建议在导入预览中标注无法自动映射的字段，允许用户手动修正

### 3.3 傻瓜式问卷设计界面

#### 3.3.1 设计流程

```
主界面 → [新建问卷] 或 [打开已有项目]
  → 问卷设计面板
  → 点击 [+ 添加题目] → 弹出题目编辑对话框
  → 填写: 问题内容 / 变量名 / 选择题型 / 设置约束
  → 点击 [确认] → 题目加入列表
  → 拖动排序题目顺序
  → 选中题目 → [设置条件规则]
  → [保存问卷]
```

#### 3.3.2 题目编辑对话框设计要点

- **题型选择**: 大图标按钮（单选 / 多选 / 固定长度填空 / 自由填空 / 条件筛选），点击即切换
- **变量名自动建议**: 根据问题内容拼音首字母自动生成建议变量名，用户可修改
- **实时校验**: 变量名是否符合规范（字母开头，仅字母数字下划线，不重复）
- **约束条件**: 根据题型自动显示对应的约束选项
  - 单选/多选 → 显示「选项列表编辑器」（添加/删除/排序/设值）
  - 固定长度填空 → 显示「长度」输入框 + 「约束类型」下拉
  - 自由填空 → 显示「约束类型」下拉（可选）

#### 3.3.3 问卷设计面板（主视图）

```
┌──────────────────────────────────────────────────────┐
│  问卷名称: [________________]  [保存] [预览] [导出]   │
├──────────────────────────────────────────────────────┤
│  # │ 题目内容          │ 变量名  │ 题型   │ 约束    │
│  1 │ 您的性别是？      │ sex     │ 单选   │ 男/女   │
│  2 │ 出生日期          │ birth   │ 日期   │ Y-M-D   │
│  3 │ 身份证号          │ id_card │ 固定长 │ 18位数字│
│  4 │ 是否吸烟？        │ smoke   │ 单选   │ 是/否🔗 │
│  5 │ 每日吸烟量(支)    │ cig_day │ 数字   │ 0-100  │ ←条件:smoke=是
│  ...                                                  │
├──────────────────────────────────────────────────────┤
│  [+ 添加题目]  [↑] [↓] 排序  [删除]  [设置条件]      │
└──────────────────────────────────────────────────────┘
```

**核实结论**: ✅ 设计合理，但建议增加：
- 题目**复制功能**（快速创建相似题目）
- 题目**分组/分页功能**（将相关题目组织在一起）
- **题目库/历史题目复用**（从已有问卷中引用题目）

### 3.4 Key 标识符设置

#### 3.4.1 功能定义

Key（个人标识符）用于唯一标识每条记录所属的个体。在流行病学调查中，通常由以下字段组合而成：

- **单一 Key**: 如身份证号、医保号
- **复合 Key**: 如 `研究ID + 随访次数`、`地区代码 + 家庭编号 + 个人编号`

#### 3.4.2 操作方式

在问卷设计时，每道题目的编辑对话框中增加一个 **「设为 Key 标识符」** 复选框。勾选后：

- 题目旁显示 🔑 图标
- Key 题目汇总显示在问卷设计面板顶部状态栏
- 系统提示：「Key 题目将用于唯一标识每份记录，请确保其组合能够唯一区分每条数据」
- 数据录入时，Key 题目自动设为必填

#### 3.4.3 Key 验证规则

- 至少设置 1 个 Key
- Key 字段的组合值必须在数据集中唯一（录入时实时检查重复）
- 若检测到重复 Key，录入界面弹出警告，阻止提交

**核实结论**: ✅ 设计合理。补充建议：
- 为复合 Key 提供「Key 模板」预览，显示组合后的格式（如 `{study_id}-{visit}-{pid}`）
- 支持「自动生成 Key」选项（如自动序号）

### 3.5 一问一屏录入模式

#### 3.5.1 显示逻辑

录入界面每次只显示一道题目，用户回答后自动/手动进入下一题。

**不会显示的题目**（已被跳题逻辑跳过的题目）不出现在录入流程中。

#### 3.5.2 界面布局

```
┌──────────────────────────────────────────────────────┐
│  ████████████████░░░░░░░░░░░░░░  进度: 5/20 (25%)    │  ← 顶部进度条
├──────────────────────────────────────────────────────┤
│                                                      │
│           第 5 题 / 共 20 题                          │  ← 题目编号
│                                                      │
│       您的最高学历是？                                │  ← 题目内容
│                                                      │
│       ○ 小学及以下                                   │
│       ○ 初中                                         │  ← 选项区域
│       ○ 高中/中专                                    │      (根据题型变化)
│       ○ 大专/本科                                    │
│       ○ 硕士及以上                                   │
│                                                      │
│       [不想回答]                                     │  ← 允许跳过(可选)
│                                                      │
├──────────────────────────────────────────────────────┤
│  [← 上一题]                    [下一题 →] [暂存退出]  │  ← 底部导航
└──────────────────────────────────────────────────────┘
```

#### 3.5.3 导航规则

| 操作 | 行为 |
|------|------|
| **下一题** | 保存当前答案 → 计算条件逻辑 → 跳转至下一可见题目 |
| **上一题** | 回到上一道已回答的题目（可修改答案） |
| **暂存退出** | 保存当前进度 → 退出到项目选择界面 → 下次可继续 |
| **键盘快捷键** | `1-9` 选择选项、`Enter` 下一题、`Esc` 暂存退出 |

#### 3.5.4 题型对应的输入组件

| 题型 | 输入组件 |
|------|----------|
| 单选题 | 大号单选按钮 (Radio)，选项垂直排列 |
| 多选题 | 复选框 (Checkbox)，选项垂直排列 |
| 固定长度填空 | 输入框 + 字符计数器（如 `15/18`） |
| 自由填空 | 多行文本输入框 |
| 日期题 | 日期选择器 / 手动输入框 |
| 数字范围 | 数字输入框 + 范围提示 + 滑块（可选） |

**核实结论**: ✅ 一问一屏是优秀的 UX 实践，可显著降低录入错误率。补充建议：
- 增加「**标记为不确定**」按钮（记录为特殊编码如 `-9`），供受访者拒绝回答或不清楚时使用
- 进度条分色显示：绿色=必答题已完成、黄色=可选待完成、灰色=已跳过题

### 3.6 录入循环与工作结束

#### 3.6.1 录入循环机制

```
录入完成最后一题

  → 自动跳转至「下一份录入」起始页（题目1重新开始）

#### 3.6.2 结束页设计

「下一份录入」起始页功能：

| 元素 | 说明 |
|------|------|
| **本批次已录入数量** | 显示「本次工作已录入: **15** 份」 |
| **已录入时间** | 显示「本批次用时: 1小时23分钟」 |
| **[开始下一份]** 按钮 | 点击后从第1题重新开始录入 |
| **[结束工作]** 按钮 | 点击后退出到项目选择界面 |
| **录入速度统计** | 平均每份用时、最快/最慢记录 |

**核实结论**: ✅ 设计合理。补充建议：
- 增加「**快速查看本次录入列表**」按钮，显示本批次录入记录的 Key 列表
- 增加「**录入员姓名/编号**」记录功能（用于双录入质控）

### 3.7 本地管理员密码与数据加密

#### 3.7.1 管理员密码机制

**密码设置流程**:
```
首次创建项目 → 提示设置管理员密码 → 输入 + 确认密码 → 
  密码通过 PBKDF2 派生密钥 → 密钥用于数据加解密 → 
  密码哈希 (bcrypt/argon2) 存储于项目配置文件中
```

**密码验证流程**:
```
用户输入密码 → 计算哈希 → 与存储的哈希比对 → 
  通过 → PBKDF2 派生解密密钥 → 解密数据文件 → 进入管理后台
```

#### 3.7.2 加密方案设计

| 加密对象 | 算法 | 说明 |
|----------|------|------|
| **管理员密码** | Argon2id（推荐）/ bcrypt | 仅存储哈希，不可逆 |
| **调查数据文件** | AES-256-GCM | 加密后以二进制格式存储为 `.easyepi_data` |
| **项目配置文件** | AES-256-GCM | 问卷结构 + 元数据加密存储为 `.easyepi_proj` |
| **解密密钥** | PBKDF2-HMAC-SHA256 | 从管理员密码 + 随机盐派生，迭代次数 ≥ 600,000 |

**安全措施**:
- ❌ 密码原文绝不写入任何文件
- ❌ 加密密钥不以明文形式存储
- ✅ 使用随机 IV（初始化向量），每次加密均不同
- ✅ 数据文件格式为二进制，非明文文本，即使被复制也无法直接读取
- ✅ 加密认证标签（GCM 模式防止篡改）

#### 3.7.3 管理员后台入口

### 3.8 数据导出与基线表生成

#### 3.8.1 数据存储格式（内部）

```
内部存储: .easyepi_data（AES-256-GCM 加密的二进制文件）
  ├── 记录以分隔符形式存储（逗号或制表符）
  ├── 每行一条记录
  ├── 首行为变量名
  └── 第二行为变量标签（可选）
```

#### 3.8.2 CSV 导出

导出后同时生成两个文件：

1. **数据文件 (CSV)**: 标准逗号分隔值，UTF-8 BOM 编码（兼容 Excel 中文打开）
2. **数据词典文件 (TXT/CSV)**: 变量名 / 标签 / 类型 / 取值范围 / 值标签映射

#### 3.8.3 多选题导出编码选项

**背景**: 多选题在数据存储时通常以单一变量存储（如逗号分隔的选项值 `"1,3,5"`）。但在统计分析中，研究者经常需要将多选题展开为多个 0/1 二分类变量。EasyEpi 在导出 CSV 时提供三种编码方式供用户选择。

**编码方式对比**:

| 编码方式 | 说明 | 列数 | 适用场景 | 示例（选项: 高血压/糖尿病/冠心病） |
|----------|------|------|----------|-------------------------------------|
| **多分类变量**（默认） | 原始存储格式，逗号分隔选项值 | 1列 | 数据存档、导入 EpiData 兼容 | `disease = "1,3"` |
| **独热编码** (One-Hot) | 每个选项独立一列，1=选中, 0=未选中 | k列 | 机器学习、逻辑回归特征 | `disease_高血压=1`, `disease_糖尿病=0`, `disease_冠心病=1` |
| **哑变量编码** (Dummy) | k-1 列，以第一个/最后一个选项为参照 | k-1列 | 回归分析（避免完全共线性） | `disease_糖尿病=0`, `disease_冠心病=1`（以高血压为参照） |

**用户操作流程**:

```
导出 CSV 对话框:
  → 选择导出范围（全部记录 / 筛选后的记录）
  → 「多选题编码方式」:
      ● 多分类变量（默认，保持原始格式）
      ○ 独热编码 (One-Hot Encoding) — 每个选项生成独立 0/1 列
      ○ 哑变量编码 (Dummy Encoding) — 以首个选项为参照
  → 选择哑变量参照选项（仅在哑变量模式下显示）:
      ┌─────────────────────────────────────┐
      │ 参照类别: [第一个选项 ▼]            │
      │           · 第一个选项              │
      │           · 最后一个选项            │
      │           · 自定义选择...           │
      └─────────────────────────────────────┘
  → [导出 CSV]
```

**编码变量命名规则**:

| 编码方式 | 变量命名格式 | 示例 |
|----------|-------------|------|
| 多分类 | `{原变量名}` | `disease` |
| 独热编码 | `{原变量名}_{选项标签/值}` | `disease_1` 或 `disease_高血压` |
| 哑变量 | `{原变量名}_{选项标签/值}_d` | `disease_糖尿病_d` |

**设计考量**:
- 编码转换仅在**导出时**进行，不影响内部存储格式。内部始终以多分类变量存储以保证数据完整性
- 独热编码和哑变量编码时，数据词典同步更新，自动生成展开后各列的变量标签
- 当多选题选项较多（>10个）时，导出时给出提示：「该多选题有 15 个选项，独热编码将生成 15 个新列，请确认」
- 如果同一问卷有多道多选题，每道题的编码方式**独立设置**（即可以部分题用原始格式、部分题用独热编码）

**核实结论**: ✅ 此功能是流行病学数据处理的关键环节。SPSS/R 用户在分析时通常需要手动编写脚本将多选题 `"1,3,5"` 展开为哑变量，EasyEpi 在导出时直接提供此功能可大幅降低用户工作量。

#### 3.8.4 基线表（Baseline Characteristics Table）生成

**这是产品的特色核心功能。** 流行病学论文中必须包含的「Table 1 — Baseline Characteristics」。

**功能描述**:
- 自动识别变量类型（连续变量 / 分类变量），分别计算均值±标准差 / 频数(%)
- 支持按分组变量（如治疗组 vs 对照组）分层统计

```

**生成示例**:

| Variable | Total (n=200) | Treatment (n=100) | Control (n=100) | P value |
|----------|---------------|-------------------|-----------------|---------|

| Sex, n(%) | | | | 0.673 |
| &nbsp;&nbsp;Male | 98 (49.0%) | 47 (47.0%) | 51 (51.0%) | |
| &nbsp;&nbsp;Female | 102 (51.0%) | 53 (53.0%) | 49 (49.0%) | |

**核实结论**: ✅ 基线表功能是 EasyEpi 与 EpiData 的关键差异点。EpiData 不具备此功能，用户通常需要导出后手动在 R/SPSS/SAS 中生成。**这是产品的核心卖点之一。**

### 3.10 衍生变量定义

#### 3.10.1 功能定位

衍生变量（Derived Variables）是基于已设计题目中采集的原始变量，通过公式计算自动生成的附加变量。典型例子：

| 衍生变量 | 公式 | 依赖的原始变量 |
|----------|------|---------------|
| BMI | `weight / (height/100)^2` | 体重(kg)、身高(cm) |
| 年龄分组 | `IF(age>=60, "老年", IF(age>=18, "成年", "未成年"))` | 年龄 |
| WHR (腰臀比) | `waist / hip` | 腰围、臀围 |
| eGFR (肾功能估算) | `186 * (creatinine^-1.154) * (age^-0.203) * (0.742 if female)` | 血肌酐、年龄、性别 |

**核心设计原则**:
- ❌ 衍生变量**不作为普通题目类型**出现（不出现在题型选择器中）
- ❌ 衍生变量**不出现在录入流程中**（录入员看不到，不手动填写）
- ✅ 衍生变量在**问卷设计完成后**，通过独立步骤定义
- ✅ 衍生变量的值在**录入完成时自动计算并存储**为数据列
- ✅ 衍生变量在导出 CSV 时作为普通列出现，标注为「衍生变量」

### 3.11 AI 问卷助手

#### 3.11.1 功能定位与范围

AI 问卷助手在已创建并解锁的项目内，通过多轮自然语言对话帮助用户从零建立或持续精细化问卷。模型负责理解研究意图并提出候选变更，本地 Harness 负责生成稳定的应用内结构、执行校验并控制写入，模型不得直接创建或覆盖 EasyEpi 项目文件。

**首版可生成内容**:

- 问卷名称与说明
- 题目内容、题型、选项、变量名与顺序
- 必填/允许跳过、默认值及答案类型、长度、范围、步长、日期、正则表达式等约束
- 单一 Key、复合 Key
- 条件、AND/OR 关系、显示/隐藏/必填等跳题规则

**首版明确不做**:

- 不生成衍生变量、公式、基线表或数据管理配置
- 不读取、分析或发送任何已录入答卷和受试者数据
- 不把模型输出未经本地校验直接保存为正式问卷
- 不依赖服务商保存 EasyEpi 的会话状态

#### 3.11.2 使用前提与隐私边界

- 用户必须先创建或打开项目并使用项目密码成功解锁，才能使用 AI 问卷助手；欢迎页和未解锁状态不得直接发起 AI 请求。
- 首次真正发送请求前提示：**「只有对话内容会被读取并发送，其余隐私信息均不会被发送和读取。」** 用户确认后方可调用 API；提示文案或数据边界版本变化后必须重新确认。
- 可发送内容仅包括用户输入的消息、模型在当前 Session 中生成的回复、由这些内容形成的对话状态，以及用户通过「加入当前问卷」明确确认的问卷内容。程序的 Prompt、Schema 和格式控制指令不包含项目隐私数据。
- AI 不得自动读取当前问卷、答卷、衍生变量、管理员数据、项目密码、恢复密钥或本地文件路径。
- 已有问卷只能由用户点击「加入当前问卷」，在发送预览中检查内容并确认后，作为对话内容发送。
- 所有核心问卷设计、录入和管理功能在离线状态下仍可用；仅 AI 问卷助手在用户主动发送时联网。

#### 3.11.3 DeepSeek API 配置

应用设置提供以下全局配置，用户只需配置一次，之后打开任意项目时默认复用：

| 字段 | 要求 |
|------|------|
| **AI 厂商** | 仅 DeepSeek 一家，不可选择；应用不提供厂商预设、厂商切换或自定义服务 |
| **服务地址** | 固定为 `https://api.deepseek.com`，以只读文本显示；应用不接受用户提供的地址，主进程会把任何非 DeepSeek 主机改写为该端点 |
| **API Key** | 以密码方式输入，界面仅显示掩码，不允许写入项目文件、日志或缓存 |
| **模型名称** | 默认 `deepseek-v4-flash`，可改为 `deepseek-v4-pro`；用户输入服务端实际支持的模型标识 |
| **检索来源** | 不是用户开关：每次生成都执行固定的检索流程（见下），医学类请求检索 PubMed、Europe PMC 与 bioRxiv/medRxiv，所有请求再由 DeepSeek Responses API 的内置联网搜索补充来源 |

- API Key 使用 Windows 操作系统安全凭据能力保存。安全凭据不可用时不得降级为明文持久化，应提示用户当前无法安全记忆密钥。
- 服务地址与模型名称保存在应用级偏好设置中，不随项目复制、备份或导出；存储格式为 schema v3（`schemaVersion`、`baseUrl`、`model`、可选的 `encryptedApiKey`、`privacyAcceptedAt`、`privacyNoticeVersion`）。
- 旧版本 v1/v2 配置自动迁移到 v3：非 DeepSeek 主机的地址被替换为 DeepSeek 端点、其模型标识重置为 `deepseek-v4-flash`、其加密 API Key 被丢弃（仅当原主机已是 DeepSeek 时保留密文与模型）；`providerId` 与 `webSearchEnabled` 字段被移除。
- 提供「测试连接」，验证认证与模型可用性；测试只发送一条固定连通性消息，不启用流式、不使用 JSON 输出模式、不触发检索，也不读取或发送项目内容。
- 问卷生成使用 Chat Completions 并要求 `response_format: { "type": "json_object" }`。`response_format` 与流式响应均作为能力增强项按服务能力独立协商降级，不得成为发送的唯一前提。
- 问卷协议不使用函数调用：任何请求都不得携带 `tools` 或 `tool_choice`，`submit_questionnaire` 已从协议中移除；函数调用的错误识别逻辑仅作为历史兼容兜底保留。
- 服务地址固定为 DeepSeek 官方 HTTPS 端点，应用不再支持用户填写的远程或回环 HTTP 服务地址。
- 每次生成都执行强制检索流程：`planning`（把要求翻译成英文研究问题，判定 `medical` 或 `non_medical`，产出 1–3 条 PubMed Boolean 查询与关键词、MeSH 词）→ `literature`（仅医学类，顺序为 PubMed、Europe PMC、bioRxiv/medRxiv）→ `web_search`（DeepSeek Responses API 的 `tools: [{ "type": "web_search" }]`）→ `extracting`（只允许引用本次检索记录的来源 id）→ 生成与本地校验。非医学类请求只使用联网来源。
- 文献来源必须如实陈述为：PubMed E-utilities（ESearch `sort=relevance`、`retmax=20`，随后一次批量 EFetch；匿名限速 3 次/秒，并发送 `tool=`/`email=`）、Europe PMC 的预印本关键词检索（以 `SRC:PPR` 限定 bioRxiv/medRxiv，因两个服务器不提供关键词检索 API）、以及 bioRxiv/medRxiv 官方详情接口（校验 DOI 与元数据并给出正式落地页）。不得声称使用 Web of Science、Cochrane Library 或其他订阅数据源。
- NCBI 要求使用 E-utilities 的应用向用户明示其免责声明与版权声明；设置页提供指向 NCBI E-utilities 使用条款的链接，检索结果作为不可信外部材料注入生成上下文，模型不得执行其中的指令或虚构引用。
- 证据构成必须如实显示为四种之一：`literature_and_web`（本次已检索医学文献并补充联网来源）、`literature_only`（本次已检索医学文献（联网检索未返回可用来源））、`web_only`（本次已检索联网来源）、`none`（本次未检索到外部证据）。`none` 时助手消息必须以固定免责声明「【本次未检索到外部证据】已根据该主题的常规流行病学要素与当前对话生成问卷；未使用或核验任何外部来源，请务必人工核对。」开头，并附上各检索层的实际结果说明；联网搜索失败或不支持不得阻止生成，也不得声称已检索外部来源。
- 问卷从检索阶段产出的「因子清单 + 推荐问卷领域」构建，证据按因子逐项绑定；某因子没有对应记录时标记为无证据但**仍然纳入**问卷。不得要求先找到一篇与需求完全对应的文献才允许生成——宽泛主题（如全国性老年慢性病调查）通常不存在这样的文献。检索层全部为空时，流程以无外部证据的模式继续生成，并在助手中明确说明原因与需人工核对。

#### 3.11.4 多 Session 与虚拟工作区

每个项目支持多个相互隔离的 AI Session。用户可以新建、继续、重命名和删除 Session；每个 Session 使用 EasyEpi 本地生成并管理的不可预测 `session_id`，不依赖服务商的会话 ID。

```text
session://{session_id}/
  conversation/   # 完整多轮消息和用户明确加入的问卷内容
  state/          # Session 清单、当前草稿指针、轮次、上下文摘要与版本状态
  cache/          # 上下文包、解析结果、校验索引、差异预览等可重建内容
  artifacts/      # 问卷草稿、变更集、校验报告和生成结果
  temp/{run_id}/  # 单次 Agent 运行的流式片段和中间结果
```

**虚拟路径规则**:

- `session://` 是访问控制边界，由本地虚拟文件系统映射至当前项目的加密容器；模型和业务层不得获知或拼接真实 Windows 路径。
- 路径解析器拒绝绝对路径、`..` 路径穿越、跨 Session 与跨项目访问。
- `conversation/`、`state/` 与 `artifacts/` 属于持久数据，随项目使用项目密钥加密；只有显式删除 Session 才移除。
- `cache/` 可安全清除并按需重新生成；`temp/` 在单次运行完成、取消或异常恢复后清理。若短暂落盘，中间数据也必须位于项目加密容器内。
- 缓存键至少包含项目、Session、Prompt 版本、Schema 版本、服务地址（固定 DeepSeek 端点）和模型标识，禁止跨项目或跨 Session 复用对话内容缓存。

#### 3.11.5 Prompt 版本控制

Prompt 不作为散落在界面代码中的字符串维护，而是进入独立版本注册表。每个 Prompt 版本至少包含：

- `prompt_id`
- 语义化版本号
- 内容哈希
- 适配的 Harness 版本与问卷 Schema 版本
- 发布时间与变更说明

每次 LLM 调用、候选变更和 artifact 都记录实际使用的 Prompt、Harness 与 Schema 版本，以便复现和审计。已存在 Session 默认固定当前 Prompt 主版本；新 Session 使用最新稳定版本。跨主版本升级必须显式迁移并保留原版本记录，禁止静默改变历史 Session 的行为。

新响应协议使用 Prompt/Harness/Model Envelope v2：根对象必须同时包含 `kind`、`assistantMessage`、`rollingSummary`、`options` 和 `questionnaire`。`kind=clarification` 时只能返回 1–5 个候选项且不生成问卷；`kind=questionnaire` 时候选项必须为空且问卷必须完整。旧 schema-1 Session 必须通过受控的显式迁移进入 schema 2：保留消息、用户已确认的问卷附件、滚动摘要、artifact 和运行/迁移审计，初始化澄清记录，清除可重建的 cache/temp 和中断运行。旧 artifact 仅作历史记录，不得在 v2 中直接应用。

#### 3.11.6 能力自适应 Harness

采用「模型提出语义变更，Harness 生成并校验应用结构」的分工：

1. Harness 从当前 Session 的 `conversation/` 与 `state/` 组装必要上下文，不读取其他项目数据。
2. 生成请求统一使用 Chat Completions 的 JSON 输出模式（`response_format: { "type": "json_object" }`）；服务明确拒绝该参数时，退回由版本化 Prompt 约束的文本 JSON 结构协议。协议不使用函数调用。
3. 模型返回用户可读说明、用于后续轮次的滚动摘要，以及“一个核心澄清问题”或“完整问卷候选”之一。澄清响应最多提供 5 个单选快捷回复，不创建 artifact；需求已足够时应直接生成。
4. Harness 解析候选变更，执行 ID 补全、顺序规范化、默认值处理和引用解析，生成独立 AI 草稿。
5. Harness 校验题型、变量名唯一性、选项、答案约束、Key、条件引用、规则冲突和循环/不可达逻辑。
6. 正常一轮优先只调用 LLM 一次。仅在结构解析或业务校验失败时，才将明确错误作为对话内容发起修复调用，最多重试两次；仍失败则保留原问卷并向用户展示错误。

允许的候选操作限定为问卷元数据和题目/选项/约束/Key/条件规则的新增、修改、删除及排序。Harness 必须拒绝衍生变量、答卷、管理员数据或任意文件操作指令。

#### 3.11.7 从零创建与已有问卷精细化

**从零创建**:

```text
创建并解锁项目 → 打开 AI 问卷助手 → 新建 Session
  → 描述研究目标、研究对象、题目与限制条件
  → 模型提出候选问卷 → Harness 校验 → 生成加密草稿
```

**精细化已有问卷**:

```text
打开 AI 问卷助手 → 点击「加入当前问卷」
  → 预览将发送的问卷内容 → 用户确认 → 内容进入当前对话
  → 描述修改目标 → 模型提出差异 → Harness 校验 → 更新加密草稿
```

未经「加入当前问卷」确认，AI Session 与正式问卷保持隔离。用户可以在同一项目内为不同研究思路建立多个 Session，Session 之间不得共享上下文或草稿。

#### 3.11.8 草稿、差异与正式应用

- 每次有效生成只更新当前 Session 的 AI 草稿，不直接修改正式问卷。
- 页面同时显示多轮对话、当前草稿/与正式问卷的新增修改删除差异、Harness 校验结果。
- 存在解析错误、无效引用、变量名冲突、约束错误或逻辑冲突时，「应用到问卷」保持禁用。
- 校验通过后，用户点击「应用到问卷」；系统先建立可恢复快照，再以原子方式写入正式问卷。
- 应用操作使用唯一 artifact/operation 标识保证幂等，网络重试或界面重复点击不得重复应用同一变更。
- 应用记录包含 Session、轮次、artifact、Prompt、Harness 与 Schema 版本，不记录 API Key。
- 正式应用失败时恢复原问卷和快照，不得留下半写入状态。

#### 3.11.9 界面与故障处理

AI 问卷助手页面至少包含：Session 列表、多轮对话窗、发送区、当前草稿/差异区、Harness 校验区，以及「加入当前问卷」「清除缓存」「应用到问卷」等操作。

发送后必须显示由应用控制的可读进度：开始、连接模型、模型生成、本地校验、自动修复、澄清/完成/失败/取消。页面只流式显示根层 `assistantMessage` 的临时可读文字，不得显示原始 JSON、Prompt、修复指令、API Key 或问卷载荷。流式 delta 和未通过校验的临时文字不持久化；只在加密 Session 中保存紧凑阶段快照、终态消息、澄清选择和经脱敏的失败摘要。离开页面后再返回时，页面根据当前运行快照继续显示阶段并恢复取消能力，不重建已错过的临时 delta。

澄清回复的 1–5 个单选按钮显示在助手消息下方；点击后立即发送由主进程按已保存选项生成的用户消息，并禁用该澄清的所有选项。普通文本输入始终可用于自由回答。

| 场景 | 系统行为 |
|------|----------|
| API 未配置 | 阻止发送并引导完成全局配置 |
| 认证失败/模型不存在 | 明确标注对应字段，不清除对话或草稿 |
| 断网、超时、限流 | 保留输入并允许安全重试；不得重复应用旧结果 |
| 用户取消流式响应 | 丢弃未完成的临时内容并清理本次运行的 `temp/`，不得形成 artifact |
| 服务不支持流式 | 仅在生成文字前收到可确认的 `stream` 不支持错误时回退为非流式，进度区明确告知；缓存限定在当前项目/Session/配置版本 |
| 上下文过长 | 使用同轮返回的滚动摘要与最近消息重建上下文；完整历史仍加密保留 |
| 输出无法解析或校验失败 | 最多两次修复调用；三次仍失败时显示中文可操作摘要、按尝试分组的安全问题和可展开技术详情，支持「根据错误重新生成」与「修改要求」，并保留正式问卷 |
| 清除缓存 | 仅清除当前 Session 的 `cache/`，不影响对话、状态、草稿与 artifacts |
| 删除 Session | 二次确认后删除该 Session 全部分区，不影响其他 Session 和正式问卷 |

流式响应是默认的等待体验，但一次用户消息仍优先只对应一次正常 LLM 生成请求。能力协商只能在没有接收任何模型文字时针对被明确拒绝的 `stream` 或 `response_format` 单独回退；超时、网络错误、无效 SSE 或已接收文字后失败均不得自动重试。提供取消能力，取消后不得把不完整输出写入 artifact。

#### 3.11.10 验收标准

可执行的 Windows 联网、故障注入、隐私边界与项目生命周期步骤见 [AI 问卷助手手动测试](AI_ASSISTANT_MANUAL_TEST.md)。

- [ ] 未创建或未解锁项目时无法调用 AI；解锁后可进入 AI 问卷助手。
- [ ] API 配置一次后可跨项目复用，API Key 不出现在项目、日志、缓存、导出或界面明文中。
- [ ] 首次发送前完成隐私确认，且未确认的当前问卷不会被读取或发送。
- [ ] 同一项目可建立多个独立 Session；重启应用后可通过 `session_id` 继续对话。
- [ ] `conversation/`、`state/`、`artifacts/` 和需要落盘的 `temp/` 均随项目加密，虚拟路径不能越界。
- [ ] 正常轮次只产生一次 LLM 调用；仅解析/校验失败时允许最多两次修复调用。
- [ ] 支持流式时能显示可读助手文字和完整阶段；`stream` 或 `response_format` 被明确拒绝时能按能力独立回退，且不显示原始 JSON。
- [ ] 配置界面只提供 DeepSeek 的模型名称与 API Key，服务地址以只读形式显示 `https://api.deepseek.com`；不存在厂商预设、自定义地址或联网搜索开关。
- [ ] 旧 v1/v2 配置自动迁移到 schema v3：非 DeepSeek 主机被替换、其模型重置为 `deepseek-v4-flash`、其加密 Key 被丢弃。
- [ ] 每次生成按 `planning → literature（仅医学类）→ web_search → extracting → 生成 → 本地校验` 执行；非医学类请求不执行文献检索。
- [ ] 医学类请求的文献检索顺序为 PubMed E-utilities、Europe PMC 预印本检索、bioRxiv/medRxiv 详情校验，并如实披露未使用任何订阅数据源。
- [ ] 界面显示的证据构成与本次实际来源一致，只能是 `literature_and_web`、`literature_only`、`web_only` 或 `none`；`none` 时必须以固定免责声明「【本次未检索到外部证据】已根据该主题的常规流行病学要素与当前对话生成问卷；未使用或核验任何外部来源，请务必人工核对。」开头并附检索结果说明。
- [ ] 医学类请求在文献与联网均无可用来源时**仍然按因子清单生成问卷**，每条因子标记为无证据，不得停止或拒绝生成。
- [ ] 模型可返回一个核心澄清问题和 1–5 个单选快捷回复；点击立即发送、选项随后禁用，且始终允许文本回答。
- [ ] 流式 delta 不持久化，终态消息/澄清/失败摘要随 Session 加密；页面返回时恢复当前阶段与取消能力。
- [ ] 连续三次校验失败后显示按尝试分组的脱敏问题、可展开技术详情和明确下一步，不暴露提示词、供应商原始响应或路径。
- [ ] schema-1 旧 Session 不得静默解释为 v2；显式迁移保留历史数据、清除可重建状态，且仅允许新 v2 artifact 应用。
- [ ] Harness 能拒绝无效变量名、失效条件引用、非法约束、重复 Key 和越权操作。
- [ ] AI 输出必须先成为草稿；只有校验通过并经用户确认后才能应用，应用前自动创建恢复快照。
- [ ] 渲染层在显示草稿前用共享校验器 `src/shared/questionnaire-format.ts` 复检；失败时标注「本地渲染校验未通过」、列出出错字段路径，且「应用到正式问卷」保持禁用。
- [ ] 缓存可按 Session 清除并重建，不影响对话、草稿或正式问卷。
- [ ] 未完成/失败/取消的运行不会污染 artifacts 或正式问卷。
- [ ] 未通过管理员验证时三个管理入口不可见且路由不可访问；管理员会话失效后立即重新隐藏。

## 4. 补充功能建议

以下功能基于对流行病学数据采集工作流的深入分析提出，用于增强产品特色和竞争力。

### 4.1 扩展题型

| 题型 | 说明 | 应用场景 |
|------|------|----------|
| **日期题** | 专门日期选择器，支持年月日 | 出生日期、调查日期 |
| **时间题** | 时:分:秒选择器 | 样本采集时间 |
| **数值滑动条** | 可视化滑块选择数值 | 疼痛评分 (0-10 VAS) |
| **图片选择题** | 选项附带图片 | 皮疹类型识别、药片辨别 |
| **矩阵/量表题** | Likert 量表矩阵（如1-5评分） | 生活质量问卷 (SF-36)、抑郁量表 (PHQ-9) |
| **排序题** | 将选项拖拽排序 | 症状优先级排序 |
| **地理位置题** | GPS 坐标采集 | 现场调查地点记录 |

### 4.2 双录入验证 (Double Data Entry)

EpiData 经典功能。两位录入员独立录入同一批数据，系统自动比对差异。

```
录入员A: 独立录入 → 数据文件A
录入员B: 独立录入 → 数据文件B
  → [双录入比对]
  → 逐字段标记不一致记录
  → 生成差异报告（列出不一致的字段和值）
  → 人工审核解决差异
```

**UI 设计**: 差异解决界面并排显示两份记录，高亮不一致字段，点击替换或跳过。

### 4.3 数据质量仪表板 (Data Quality Dashboard)

实时展示数据质量指标：完整率、异常值、逻辑矛盾、重复记录。帮助项目负责人快速评估数据采集质量。

### 4.4 问卷模板系统

预置常用流行病学标准化问卷模板：
- **PHQ-9** (抑郁症筛查)
- **GAD-7** (焦虑症筛查)
- **SF-36** (生活质量)
- **WHOQOL-BREF** (世界卫生组织生活质量简表)
- 用户可自定义模板并分享

### 4.5 逻辑冲突检测 (Logic Conflict Detection)

在设计问卷时，系统自动检测逻辑冲突：
- 题目A 的跳题规则覆盖了题目B，但题目B也有独立的显示条件 → 冲突警告
- 某题在一条规则中设为必填，在另一条规则中被跳过 → 冲突警告
- 未引用题目标记（某题在所有规则路径下均不会显示）→ 提醒

### 4.6 高级衍生变量（远期扩展）

基础衍生变量功能已在 [§3.10](#310-衍生变量定义) 中作为核心功能定义。远期规划中可在基础函数库之上进一步扩展：

- **聚合函数**: 基于多道题目的值的汇总计算（如三次血压测量的均值）
- **外部查表**: 引用外部医学参考值表格（如儿童生长曲线百分位数）
- **动态变量**: 录入时实时计算，在录入界面中同步显示（如录入身高体重后立即看到 BMI）

### 4.7 自动备份与版本管理

- **自动备份**: 每次保存时自动创建备份（保留最近 N 个版本）
- **定时备份**: 可配置时间间隔（如每30分钟）
- **版本回滚**: 从备份列表恢复至任意历史版本
- **变更日志**: 记录每次问卷修改的内容和时间

### 4.8 问卷预览与打印

- **录入模式预览**: 以录入员视角完整走一遍问卷，测试所有跳题逻辑
- **纸质版打印**: 导出问卷的「纸质友好」版本（紧凑排版，适合打印后用于现场调查）
- **PDF 导出**: 导出带格式的 PDF 文档

### 4.9 录入员管理

- 支持「录入员账号」概念（无需密码，仅用于标识）
- 录入员 A 登录 → 录入数据标记来源
- 支持录入工作量统计

### 4.10 数据词典自动生成

导出的数据词典包含：
- 变量名（英文）
- 变量标签（中文）
- 变量类型（数值/分类/文本/日期）
- 取值范围或选项列表
- 值标签映射（如 `1=男, 2=女`）
- 缺失值编码（如 `-9=不适用, -8=拒绝回答`）

可直接导入 R (`haven`), SPSS, SAS 使用。

### 4.11 紧急恢复密钥 (Recovery Key)

在设置管理员密码时，系统生成一个 12 词的 BIP39 恢复短语：
- 用户可打印或安全保存
- 遗忘密码时，输入恢复短语可以重置密码
- 恢复操作记录在审计日志中

### 4.12 多语言支持

- 应用界面语言：中文 / 英文（一期仅中文）
- 问卷语言：支持同一问卷的多语言版本（中文题面 vs 英文题面）
- 便于国际合作项目

## 5. 非功能性需求

### 5.1 性能要求

| 指标 | 要求 |
|------|------|
| 应用启动时间 | < 3秒 |
| 项目加载时间（1000条记录） | < 2秒 |
| 题目间切换延迟 | < 100ms（即时） |
| CSV导出（10000条记录） | < 30秒 |
| 内存占用（空闲） | < 200MB |
| AI 发送后的本地状态反馈 | < 100ms；模型首字节与完成时间受第三方服务影响，不纳入本地性能承诺 |
| AI 正常轮次调用次数 | 1 次；仅解析或校验失败时额外修复，最多总计 3 次 |

### 5.2 安全要求

| 要求 | 说明 |
|------|------|
| 静态数据加密 | 所有敏感数据文件使用 AES-256-GCM 加密 |
| 密码存储 | 使用 Argon2id 哈希，不存储明文 |
| 内存安全 | 解密后的数据在使用完毕后立即从内存中清除 |
| 临时文件 | 导出操作不产生未加密的临时数据文件残留 |
| API 凭据 | API Key 使用 Windows 安全凭据保存，不得进入项目文件、日志、缓存或导出 |
| AI 数据最小化 | 仅发送当前对话及用户明确加入的问卷内容，不读取或发送答卷、密码和其他项目隐私数据 |
| 传输安全 | 核心功能无网络传输；AI 仅在用户主动发送时连接固定的 DeepSeek HTTPS 端点（`https://api.deepseek.com`），不提供用户自定义地址 |
| 虚拟路径隔离 | Session 仅经 `session://` 访问，阻止真实路径泄露、路径穿越及跨项目/Session 读取 |

### 5.3 可用性要求

| 要求 | 说明 |
|------|------|
| 界面语言 | 简体中文（一期） |
| 最低屏幕分辨率 | 1366×768 |
| 键盘操作 | 主要操作支持纯键盘完成 |
| 字体大小 | 支持标准/大字体两种模式 |
| AI 可恢复性 | 断网、取消或模型错误不得丢失已保存对话、草稿或正式问卷 |

### 5.4 兼容性要求

| 平台 | 版本要求 |
|------|----------|
| Windows | Windows 10 及以上（64位） |
| macOS | 当前版本不支持 |
| EpiData 兼容 | EpiData 3.1 / EpiData Manager v1.4+ / EpiData Entry Client |
| AI API | 仅 DeepSeek（`https://api.deepseek.com`）：Chat Completions 的 JSON 输出模式与 Responses API 的内置联网搜索；`response_format`、流式响应与联网工具按能力协商，不使用函数调用 |
