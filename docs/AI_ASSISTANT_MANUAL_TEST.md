# AI 问卷助手手动测试

本文用于 Windows 发布前手动验收。建议每轮记录应用版本、Windows 版本、项目路径、服务 Base URL、模型名、代理/服务端请求计数和实际结果；API Key 只记录为“已配置”，不要粘贴到测试记录。

## 1. 前置条件与测试服务

- Windows 10/11 x64；准备两个使用不同密码的测试项目 A、B，并能正常创建、打开和解锁。
- 准备一个 OpenAI-compatible 服务，配置 Base URL、API Key 和模型。基线协议是 Chat Completions：应用向 `POST <Base URL>/chat/completions` 发送请求，并读取 `choices[0].message.content` 字符串。
- 兼容 URL 示例：`https://ai.example.org/v1`、`https://gateway.example.org/openai/v1`、`http://127.0.0.1:8000/v1`。HTTP 只允许 `localhost`、`127.0.0.1` 或 `[::1]` 回环地址；不要使用带账号、密码、查询串或片段的 URL。Base URL 已以 `/chat/completions` 结尾时不会重复追加。
- 推荐模型至少能遵循多轮指令、输出单个 JSON 对象、返回完整问卷候选并在收到本地校验错误后修正。响应包应包含 `assistantMessage`、`rollingSummary`、`questionnaire`；不要求工具调用、流式响应或原生 JSON Schema。
- 准备可查看并计数请求的本地兼容服务或 HTTPS 调试代理，以及可按脚本返回 400/401/403/404/429、延迟、断连和指定响应内容的 stub。代理必须脱敏 `Authorization`，测试捕获文件不得进入提交或正式日志。
- 使用独立测试项目目录和独立 Electron userData。打包版默认 userData 通常位于 `%APPDATA%\EasyEpi`，最终以实际启动参数/环境为准；全局 AI 配置文件名为 `ai-provider-config.json`。
- 编译、typecheck 或 build 只能证明类型和产物可生成，不能证明真实服务的认证、模型能力、错误体格式、超时、限流或 JSON Schema 降级行为；以下联网项目必须观察真实请求或受控 stub。

建议给测试 API Key、消息和问卷分别使用唯一标记，例如 `AI_KEY_SENTINEL_...`、`AI_CHAT_SENTINEL_...`、`AI_QNAIRE_SENTINEL_...`，便于结束后扫描明文旁路。

## 2. 配置、安全存储与隐私

### MT-AI-01 全局配置跨项目复用

- **操作**：解锁项目 A，在右上角“设置 → AI 服务”填写 Base URL、模型和 API Key，保存并测试连接；关闭 A，创建或打开项目 B，再打开设置和 AI 问卷助手。
- **预期**：B 自动复用相同 Base URL、模型和“已保存 Key”状态；无需再次录入。测试连接只发送固定连通性消息，不发送任何项目内容。
- **注意点**：配置属于应用级 userData，不应写进 A/B 的 `.easyepi`、`.easyepi_data` 或 `.backups`。页面要求三项完整保存后才能发送。

### MT-AI-02 Key 不回显、保留与清除

- **操作**：保存 Key 后关闭并重开设置；只修改模型并让 Key 输入框保持空白后保存；再点击“清除 API 配置”。
- **预期**：已保存 Key 从不以明文回填，只显示“已安全保存”语义/掩码；空白保存保留原 Key；清除后 Base URL 回到默认值、模型为空、Key 状态为空，AI 页面阻止发送。
- **注意点**：清除 API 配置会保留已经接受的隐私确认，因此配置文件可能仍存在。不要把掩码误认为真实 Key。

### MT-AI-03 safeStorage 不可用

- **操作**：使用能将 Electron `safeStorage.isEncryptionAvailable()` 固定为 `false` 的测试构建/故障注入启动；尝试保存新 Key。另用已含密文配置的隔离 userData 启动并测试连接。
- **预期**：保存或解密返回“当前系统安全存储不可用”，Key 不会降级为明文保存，AI 请求不会发出；已有配置文件不会被改写成明文。
- **注意点**：实现依赖 Electron `safeStorage` 与 Windows OS-backed encryption，不要在测试记录中写成“Credential Manager”。普通 Windows UI 没有可靠开关可模拟此故障，必须使用受控测试构建或注入。

### MT-AI-04 首次隐私确认只出现一次

- **操作**：用全新 userData 配置服务，在项目 A 第一次点击发送；逐字核对提示，先“暂不接受”，再次发送后选择“接受并发送”；在同一项目再发一轮，随后切到项目 B 再发送；清除并重配 API 后再发送。
- **预期**：精确文案为“只有对话内容会被读取并发送，其余隐私信息均不会被发送和读取。”；暂不接受时不产生网络请求且输入保留；接受后才发送。接受记录在文案/边界版本不变时全局只确认一次，后续轮次、项目 B 和清除/重配 API 后均不重复弹出。
- **注意点**：必须从“真正发送”触发，打开页面或测试连接不算首次发送。若未来隐私文案或数据边界版本变化，应单独验证重新确认。

### MT-AI-05 未附加问卷的数据最小化

- **操作**：在 A 中预先准备带唯一标记的项目路径、项目密码、答卷、基线结果、管理员数据、衍生变量和正式问卷；新建 AI Session，只发送带 `AI_CHAT_SENTINEL` 的消息，不点击“加入当前问卷”。查看脱敏后的代理/服务请求体。
- **预期**：请求只含版本化系统指令、当前 Session 的用户/助手消息、滚动摘要等 Session 上下文；若 Session 已有 AI 草稿，可含该 Session 的 active draft。请求不得含真实 Windows 路径、密码/恢复材料、答卷、基线、管理员数据、衍生变量或未明确加入的正式问卷标记。
- **注意点**：系统 Prompt、Schema、修复错误属于协议控制内容，不是项目隐私。代理日志本身会看到允许发送的对话，必须隔离、脱敏并在验收后删除，不能把代理捕获误判为应用旁路日志。

## 3. 问卷生成、附加与 Session

### MT-AI-06 从零生成问卷

- **操作**：在空问卷项目中新建 Session，描述研究对象、题目、类型、选项、Key 和跳题规则并发送；检查返回草稿、差异和校验状态，不点击应用。
- **预期**：可从 0 生成完整草稿；页面显示本地校验通过、完整草稿摘要和相对空正式问卷的差异；正式问卷仍为空。
- **注意点**：模型只提出候选，必须先形成 artifact；失败输出或未校验输出不能修改正式问卷。

### MT-AI-07 显式加入当前问卷与重新确认

- **操作**：给正式问卷加入元数据、题目、全部选项/约束/Key 和条件规则，并创建一个衍生变量。点击“加入当前问卷”，逐步展开并核对完整预览，确认加入但暂不发送；然后在问卷设计页修改一个题目，回到 AI 页面发送。重新预览确认后再发送并查看请求体。
- **预期**：首次弹窗展示问卷名、说明、题目完整快照、条件规则完整快照和 Key；只有点击“确认加入”后本轮才标记附加。确认后若正式问卷发生修改，发送被拦截并显示更新后的完整快照，要求重新确认。最终请求含确认时的问卷完整结构，但不含 `derivedVariables` 或衍生变量标记。
- **注意点**：“确认加入”只对本次发送有效，发送完成后自动取消附加状态；不要只核对题目计数，应展开到最后一题和最后一条规则。

### MT-AI-08 多轮细化与多个 Session 隔离

- **操作**：Session 1 从零生成草稿，连续要求改题、加规则和调整顺序；新建 Session 2，提出完全不同主题且不提 Session 1 的唯一标记；来回切换两个 Session，并分别重命名。
- **预期**：Session 1 每轮以上一轮对话/草稿继续细化；Session 2 不出现 Session 1 的消息、摘要、草稿或标记；切回时各自历史、状态和 active artifact 保持独立。
- **注意点**：用代理按 Session 轮次核对上下文；服务商会话 ID 不应成为本地隔离依据。

### MT-AI-09 关闭重开续接与虚拟分区

- **操作**：保存/关闭项目 A，退出应用，重开应用并解锁 A；继续原 Session 发一轮。随后检查项目目录、userData 和临时目录是否出现以 session ID 命名的目录。
- **预期**：原 Session 列表、消息、状态和 artifact 可续接；`conversation`、`state`、`cache`、`artifacts`、`temp` 是项目加密载荷内的逻辑分区，不存在真实 `session://` 路径或 session 目录。完成/失败/取消后的 run temp 被清理，启动恢复也会清理中断 temp。
- **注意点**：`session://{id}/...` 是虚拟寻址语法，不应在文件系统中创建目录；缓存能力也随项目加密，不写成项目外明文缓存。

## 4. 调用次数、兼容性与错误处理

### MT-AI-10 正常一次调用与最多两次修复

- **操作**：清零代理计数，让 stub 第一次返回可通过 Harness 的完整候选；再分别运行“第 1 次无效、第 2 次有效”和“连续 3 次无效”的脚本。
- **预期**：正常轮次只有 1 次模型调用。第一次无效时最多增加 2 次修复，总调用数不超过 3；第 2 次有效即停止；连续 3 次无效时显示本地校验失败，不形成可应用 artifact，正式问卷不变。
- **注意点**：`json_schema` 不支持所引起的同轮协议降级是传输兼容重试，应单独按 MT-AI-12 计数，不要混作 Harness 修复。

### MT-AI-11 取消、断网和稳定错误映射

- **操作**：逐项使用 stub/网络控制制造长响应后取消、断网/拒绝连接、401、403、404、429 和超过 60 秒的响应；每项前记录现有消息、草稿和正式问卷。
- **预期**：取消显示“AI 请求已取消”；断网显示网络错误；401/403 显示认证失败；404 显示模型不存在；429 显示服务繁忙/限流；超时显示响应超时。所有场景均不产生不完整 artifact、不修改正式问卷，已保存历史和旧草稿仍可读取，可安全重试。
- **注意点**：404 在当前协议中统一映射为模型未找到；用代理确认取消确实中止连接。超时以应用默认 60 秒为准，测试环境若注入其他 timeout 要记录实际值。

### MT-AI-12 `json_schema` 不支持时回退文本协议

- **操作**：让 stub 首次对带 `response_format.type=json_schema` 的请求返回 400 或 422，错误体同时明确包含 `response_format`/`json_schema` 和 `unsupported`/`not support`/`unknown`/`unrecognized`/`invalid parameter` 之一；第二次对不带 `response_format` 的同内容请求返回有效 Chat Completions。再在同一 Session 发下一轮。
- **预期**：当前轮自动重试且第二次请求移除 `response_format`，仍生成合格草稿；兼容能力写入当前项目/Session 的加密 cache，下一轮直接使用文本协议。
- **注意点**：只有 400/422 且错误体能明确识别“不支持 response format”才降级；其他错误不得静默降级。文本响应的 `message.content` 仍必须是 Harness 可解析的 JSON 文本。

## 5. Artifact、应用与恢复

### MT-AI-13 diff、校验与 stale 拒绝

- **操作**：对已有问卷生成包含新增、修改、删除和规则变更的草稿，人工对照 diff；生成后先在设计页修改正式问卷，再返回尝试查看/应用旧草稿。
- **预期**：diff 的元数据、题目新增/修改/删除和规则计数与完整草稿一致；只有 Harness 成功的 artifact 可应用。正式问卷修订后，旧 artifact 显示“需重新生成”或 stale 错误，应用按钮不可用/请求被拒绝。
- **注意点**：stale 依据 `questionnaireRevision` 与基线哈希，不以页面是否刷新作为判断；衍生变量变化另由应用前冲突校验保护。

### MT-AI-14 应用前备份、衍生保留与幂等

- **操作**：先给正式问卷创建可计算的衍生变量；生成并确认应用一个校验通过的草稿。应用前后列出项目目录的 `.backups`，核对问卷和衍生变量。使用相同 artifact/operation 再次触发 apply（可用受控测试壳或 IPC 调试入口）。
- **预期**：正式写入前新增加密项目备份；草稿内容写入正式问卷，但原衍生变量原样保留且仍通过校验；相同操作第二次返回“已应用”/`applied: false`，不重复变更、备份或刷新问卷内容。
- **注意点**：实际备份目录名是 `.backups`；若衍生变量引用与新草稿冲突，必须拒绝应用并保留两者原状。

### MT-AI-15 应用失败回滚

- **操作**：使用故障注入让 apply 的原子保存步骤在备份成功后失败；记录应用前正式问卷、`questionnaireRevision`、Session active artifact 和衍生变量，再点击确认应用并重开项目核对。
- **预期**：显示应用失败；内存与重开后的正式问卷、修订号、项目元数据、AI Session 状态和衍生变量均回到应用前；原 artifact 仍可查看，备份可用于恢复，不留下半应用状态。
- **注意点**：不要用杀进程代替精确的保存失败注入，否则无法区分应用回滚与操作系统崩溃恢复。

## 6. 项目生命周期与管理员权限

### MT-AI-16 改密与项目切换取消在途请求

- **操作**：让 A 的 AI 请求保持在途；以已登录管理员执行改密。另起一轮在途请求后关闭 A 或打开/创建 B；观察代理连接、页面和两个项目文件，随后用新密码重开 A。
- **预期**：改密会先取消并等待在途 AI 请求结束，再重加密；关闭、创建、打开、恢复/替换项目会取消旧项目请求。迟到响应不得写入 A 或 B；页面清空旧 Session 选择并要求在当前项目重新选择。A 用新密码可打开，历史已完成内容仍在。
- **注意点**：项目切换同时使管理员会话失效；失败/取消轮次不得形成 artifact。记录代理端连接关闭时间以排除“只在 UI 隐藏”的假取消。

### MT-AI-17 管理员三侧栏入口不受 AI 改动影响

- **操作**：分别在未登录、登录成功、等待会话过期、从 A 切到 B 四种状态检查桌面侧栏和紧凑导航，并直接输入管理路由。三入口为“数据管理”“基线表”“衍生变量”。同时确认“AI 问卷助手”始终是非管理员入口，但仍要求项目已解锁。
- **预期**：未登录时三入口均隐藏，直接访问受保护路由跳到管理员验证；登录后同时显示并可访问；过期后立即隐藏，当前受保护页跳回管理员验证；切项目后旧管理员会话失效，三入口再次隐藏。AI 入口的显示不授予任何管理员权限，也不改变三入口守卫。
- **注意点**：另有受保护的“双录入验证”路由由数据管理页进入，不属于本项“三侧栏入口”；桌面和窄屏紧凑导航都要检查。

## 7. 明文旁路与配置文件终检

### MT-AI-18 项目、备份、日志和配置文件扫描

- **操作**：完成以上测试并正常退出应用。用唯一标记扫描项目目录（含 `.easyepi`、`.easyepi_data`、`.backups`）、userData、应用本地日志和系统临时目录；单独打开 `ai-provider-config.json`。可在 PowerShell 使用 `rg -a -n --fixed-strings 'AI_KEY_SENTINEL' <目录>` 和对话/问卷标记重复扫描。
- **预期**：API Key 明文不出现在项目、备份、缓存、临时文件或应用日志；真实对话/问卷只存在于加密项目载荷，不在项目旁路文件、userData 或应用日志出现明文。配置文件只含 schema 版本、Base URL、模型、Electron safeStorage 产生的 `encryptedApiKey` 密文及可选隐私接受时间，不含 `apiKey` 明文或真实对话。
- **注意点**：代理/服务捕获是本测试有意创建的远端可见副本，应先核对允许字段，再安全删除后执行本地终检。加密项目/备份中可以有密文命中随机字节的极低概率；真正失败证据应是可读的完整唯一标记。Electron safeStorage/Windows OS-backed encryption 是准确表述，不要声称固定使用某个 Windows 凭据管理产品。

## 8. 结果记录

每项记录 `PASS / FAIL / BLOCKED`、实际请求次数、错误码/界面文案、代理请求编号和必要截图。任何 FAIL 至少附：复现步骤、项目是否已解锁、Session ID（可记录）、artifact/operation ID（可记录）、模型名、是否启用 JSON Schema、正式问卷是否变化；不得附 API Key、密码、恢复密钥、真实答卷或未脱敏请求头。
