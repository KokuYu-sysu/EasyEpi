## 1. 总体流程与阶段划分

### 1.1 核心原则：设计先行，迭代推进

**UI 设计在开发之前先行，但不是"全部设计完再开发"。** 正确的做法是：

```
全局设计系统（先做）
    ↓
逐个模块：UI 原型 → 技术评审 → 开发实现 → 测试验收 → 交付
    ↑_________________________________________________↓
                  （迭代循环，每 2-3 周一轮）
```

| 阶段 | 名称 | 时长 | 设计投入 | 开发投入 | 交付物 |
|------|------|------|----------|----------|--------|
| **0** | 项目初始化 | 1 周 | 无 | 100% | 项目骨架、CI/CD |
| **1** | 设计系统 + UI 基础设施 | 2 周 | **80%** | 20% | 设计 Token、组件库、原型 |
| **2** | 问卷设计引擎 | 4 周 | 30% | 70% | 可用的问卷设计模块 |
| **3** | 数据录入系统 | 4 周 | 30% | 70% | 可用的录入模块 |
| **4** | 数据管理与导出 | 3 周 | 20% | 80% | 管理后台 + CSV/基线表 |
| **5** | EpiData 兼容层 | 3 周 | 15% | 85% | .qes/.rec 导入 |
| **6** | 高级特性 | 4 周 | 25% | 75% | 衍生变量、编码导出 |
| **7** | 打磨与发布 | 3 周 | 40% | 60% | 安装包、文档 |

### 1.2 为什么设计系统必须在开发之前完成

| 如果没有先做设计系统 | 后果 |
|---------------------|------|
| 每个开发者自行选择颜色/间距/圆角 | 界面风格不统一，像拼凑的 |
| 组件没有统一规范 | 同样的按钮在不同页面外观不同 |
| 没有动画/过渡标准 | 交互感受粗糙 |
| 后期统一风格需要大量返工 | 延期 + 士气低落 |

**结论**：阶段 1（设计系统）必须在功能开发启动前完成。之后的每个功能模块在开发前，设计师先出该模块的高保真原型，开发拿到原型和设计 Token 后开始编码。
