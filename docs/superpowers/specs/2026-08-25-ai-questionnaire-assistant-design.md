# EasyEpi AI 问卷助手与管理员导航权限设计

> 日期：2026-08-25
> 状态：已确认，待用户复核书面规格
> 产品需求来源：[PRD §3.11](../../PRD.md#311-ai-问卷助手)

## 1. 目标

在 EasyEpi 发布前加入内置 AI 问卷助手。用户在创建并解锁项目后，可以通过兼容 OpenAI Chat Completions 协议的模型，以多轮对话从零创建问卷，或在明确确认发送现有问卷后持续精细化。模型只负责理解和提出候选变更；本地 Harness 负责格式、业务规则、安全与正式写入。

同时收紧管理员导航：只有管理员验证成功后，侧栏才显示「数据管理」「基线表」「衍生变量」，并在路由和主进程层执行相同授权。

## 2. 已确认边界

### 2.1 AI 可操作对象

首版支持问卷名称与说明、题目、题型、选项、变量名、顺序、必填/跳过、默认值、答案约束、Key 和条件跳题规则。

首版不生成衍生变量，不读取或操作答卷、基线表、管理员数据，不执行任意文件操作，也不允许模型直接写 EasyEpi 文件。

### 2.2 联网和隐私

核心功能继续支持完全离线。AI 仅在用户主动发送时联网。首次发送前显示：「只有对话内容会被读取并发送，其余隐私信息均不会被发送和读取。」

AI 可以接收用户消息、当前 Session 内的模型回复及对话状态。已有问卷必须由用户点击「加入当前问卷」，检查发送预览并确认后，才成为对话内容。AI 不自动读取项目问卷、答卷、密码、恢复密钥或本地路径。

## 3. 总体架构

```text
AI 页面
  ├─ 全局 API 配置（Base URL / API Key / 模型）
  ├─ Session 列表与多轮对话
  ├─ 草稿、差异和校验结果
  └─ 应用到问卷
          │
          ▼
AI Orchestrator
  ├─ Prompt Registry
  ├─ Context Builder
  ├─ OpenAI-compatible Client
  ├─ Capability Adapter
  └─ Virtual Session FS
          │
          ▼
Questionnaire Harness
  ├─ 候选操作解析与规范化
  ├─ Questionnaire Schema 校验
  ├─ 业务规则与引用校验
  ├─ 草稿/差异/artifact 管理
  └─ 快照后原子应用
```

各组件职责保持隔离：API Client 不接触项目文件；虚拟存储层不理解问卷语义；Harness 不持有 API Key；页面不能绕过 Harness 写正式问卷。

## 4. 全局 API 配置

- 配置字段为 Base URL、API Key、模型名称，应用级保存并跨项目复用。
- API Key 使用 Windows 安全凭据保存，界面仅显示掩码；安全存储不可用时不允许明文持久化。
- Base URL 和模型名称保存于应用偏好，不进入项目、备份或导出。
- 「测试连接」只验证服务、认证和模型，不读取项目内容。
- 基线兼容 OpenAI Chat Completions；JSON Schema、工具调用和流式响应为能力增强。
- 远程 API 使用 HTTPS；回环地址上的本地兼容服务可使用 HTTP。

## 5. Session 与虚拟存储

`session_id` 由 EasyEpi 生成和管理，服务商保持无状态。一个项目可以有多个独立 Session。

```text
session://{session_id}/
  conversation/   完整多轮消息和明确加入的问卷
  state/          会话清单、轮次、草稿指针、上下文摘要和版本状态
  cache/          可重建上下文包、解析结果、校验索引和差异预览
  artifacts/      问卷草稿、变更集、校验报告和生成结果
  temp/{run_id}/  单次 Agent 运行的流片段与中间结果
```

虚拟路径映射至当前项目的加密容器，拒绝绝对路径、路径穿越、跨 Session 和跨项目访问。模型不接触真实 Windows 路径。

`conversation/`、`state/`、`artifacts/` 持久保留，直到用户删除 Session。`cache/` 可清除并重建。`temp/` 在运行结束、取消或恢复后清理；若落盘也必须加密。

缓存键至少包括项目、Session、Prompt、Schema、Base URL 和模型标识，不共享对话内容缓存。

## 6. Prompt 版本控制

Prompt 进入独立注册表，每个版本记录：`prompt_id`、语义化版本、内容哈希、Harness/Schema 兼容版本、发布时间和变更说明。

每次调用和 artifact 记录实际 Prompt、Harness 与 Schema 版本。历史 Session 默认固定 Prompt 主版本；新 Session 使用最新稳定版本。主版本迁移必须显式执行，禁止静默改变历史行为。

## 7. Harness 与调用策略

正常一轮只进行一次 LLM 调用：Harness 组装当前 Session 的必要上下文，模型在同一响应中返回说明、候选问卷操作和滚动上下文摘要。

服务支持 JSON Schema 或工具调用时优先使用；否则使用版本化文本协议。Harness 随后：

1. 解析候选操作；
2. 补全 ID、顺序和默认值；
3. 解析题目和条件引用；
4. 校验题型、变量名、选项、约束、Key 和逻辑规则；
5. 写入隔离的 AI 草稿和 artifact。

结构或业务校验失败时，将错误反馈给模型修复，最多额外调用两次。仍失败则只展示错误，不改草稿或正式问卷。越权操作直接拒绝。

## 8. 用户流程

### 8.1 从零生成

```text
创建并解锁项目 → AI 问卷助手 → 新建 Session
  → 描述问卷 → 单次模型调用 → Harness 校验
  → 加密草稿与差异 → 用户确认 → 快照 → 正式问卷
```

### 8.2 修改已有问卷

```text
AI 问卷助手 → 加入当前问卷 → 发送预览 → 用户确认
  → 描述修改 → 模型候选变更 → Harness 校验
  → 差异预览 → 用户确认 → 快照 → 正式问卷
```

草稿始终与正式问卷隔离。校验错误时禁用应用。应用使用唯一 operation/artifact 标识保证幂等，并以原子写入避免半成品。

## 9. 错误和恢复

- 缺少 API 配置：阻止发送并定位到配置。
- 认证失败或模型不存在：标记具体字段，不删除对话和草稿。
- 断网、超时或限流：保留输入并允许幂等重试。
- 用户取消：不完整响应只存在于 `temp/`，不形成 artifact。
- 上下文过长：使用同轮生成的滚动摘要和最近消息，完整历史继续加密保留。
- 解析/校验失败：最多两次修复调用；失败后保留正式问卷。
- 应用失败：恢复原问卷和快照，不留下半写入状态。

## 10. 管理员导航权限

- 未验证时只显示「管理员验证」，桌面与紧凑导航均不渲染三个管理入口。
- 验证成功后显示「数据管理」「基线表」「衍生变量」。
- 空闲 30 分钟、主动退出、切换项目、项目锁定或关闭应用后立即隐藏。
- 路由守卫和主进程 IPC 同时校验当前项目绑定的管理员会话。
- AI 问卷助手只要求项目解锁，不要求管理员验证。

## 11. 测试重点

- 全局凭据跨项目复用且 API Key 不泄漏至项目、日志、缓存或导出。
- 隐私确认与「加入当前问卷」发送预览不可绕过。
- Session 加密续接、分区生命周期、虚拟路径穿越和跨 Session 隔离。
- Prompt/Schema 版本固定、迁移和 artifact 可追溯性。
- JSON Schema 与文本协议两条兼容路径。
- 单次正常调用、最多两次修复调用和取消清理。
- Harness 的变量名、约束、Key、条件引用、逻辑冲突和越权拒绝。
- 草稿隔离、差异预览、应用幂等、快照与失败回滚。
- 管理员菜单显示/隐藏、直接路由访问与 IPC 越权测试。

## 12. 非目标

本设计不包含实现计划、具体组件库选型、服务商账号体系、云端会话同步、在线问卷发放、衍生变量 AI 生成和答卷分析。
